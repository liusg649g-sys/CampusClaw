# Design

## Context

当前 CampusClaw 已经具备班级、课程材料上传和材料管理等功能，但材料主要以文件形式保存，尚未形成可检索的班级知识库。

本次变更需要在现有班级与材料体系基础上增加知识检索能力，并确保不同班级之间的数据相互隔离。相关功能要求见 `proposal.md` 和 `specs/class-knowledge-base/spec.md`。

由于检索结果需要支持语义匹配和内容溯源，因此系统需要在保存可检索内容时，同时保存所属班级和来源信息。

## Goals / Non-Goals

**Goals:**

- 将班级课程材料处理为可检索的知识内容。
- 支持用户在当前班级范围内进行知识检索。
- 保证检索不会返回其他班级的知识内容。
- 为检索结果提供来源文件名、页码或其他可用的来源信息。
- 采用结构相对简单、适合本地开发和课程作业的实现方案。

**Non-Goals:**

- 本次设计不实现跨班级知识库检索。
- 本次设计不实现复杂的知识图谱。
- 本次设计不要求实现大规模分布式向量检索。
- 本次设计不要求使用大型语言模型生成最终答案，重点是知识内容检索与来源展示。

## Decisions

### 1. 使用文本分块构建知识库

教师上传的课程材料在进入知识库前，需要先提取文本内容，并按照一定长度切分为多个文本片段。

每个文本片段作为独立的知识条目进行存储和检索。

选择文本分块的原因是，相比直接对整份文件进行检索，较小的文本片段可以提高检索结果的相关性，也方便定位内容来源。

备选方案是直接以整份文件作为检索单位，但这种方式粒度过大，不利于返回具体相关内容，因此不采用。

### 2. 使用向量检索支持语义搜索

系统将文本片段转换为向量，并使用向量相似度进行检索。

本次实现可优先考虑使用 Chroma 作为轻量级向量存储，因为其部署简单，适合本地开发和课程作业场景。

备选方案包括 FAISS、pgvector 和其他向量数据库。FAISS 更偏向向量索引库，额外的元数据管理需要自行处理；pgvector 需要 PostgreSQL 环境，部署成本相对更高。因此本次优先考虑 Chroma。

### 3. 每个知识片段保存班级元数据

每个知识片段除保存文本内容和向量外，还需要保存以下元数据：

- `class_id`：所属班级标识
- `source_file`：来源文件名
- `page`：页码（如果能够提取）
- `chunk_index`：文本片段编号

通过保存 `class_id`，系统可以在检索时限定班级范围。

### 4. 检索时先限定班级范围

用户提交检索请求时，后端首先确定当前用户正在访问的班级。

向量检索必须增加 `class_id` 过滤条件，只查询当前班级的知识内容。

系统不能先查询所有班级内容后再在前端过滤，因为这样可能造成跨班级数据泄漏。

班级范围限制应由后端完成。

### 5. 返回结果时同时返回来源信息

检索结果不仅包含匹配到的知识内容，还需要包含对应的来源元数据，例如：

- 来源文件名
- 页码
- 文本片段编号

前端可以在知识检索结果下方显示“来源：xxx.pdf，第 x 页”等信息，实现内容溯源。

### 6. 知识库检索流程

整体流程如下：

教师上传班级材料  
→ 后端读取文件内容  
→ 提取文本  
→ 文本分块  
→ 生成文本向量  
→ 保存向量和元数据  
→ 用户提交问题  
→ 后端确定当前班级  
→ 按 `class_id` 过滤并进行向量检索  
→ 返回相关文本片段  
→ 同时返回来源信息  
→ 前端展示检索结果和来源

## Risks / Trade-offs

- [文本提取失败或格式复杂] → 首先支持较常见的文本类和 PDF 文档，对无法解析的文件返回明确提示。
- [向量检索结果不够准确] → 调整文本分块大小和检索返回数量，并为后续更换 embedding 模型保留空间。
- [不同班级内容发生混用] → 将 `class_id` 作为知识片段的必要元数据，并在后端检索阶段强制过滤。
- [部分文件无法提供页码] → 页码不是强制字段，无法获取时至少保留来源文件名和文本片段编号。
- [新增向量存储增加项目依赖] → 优先选择轻量级、可本地运行的方案，减少部署复杂度。

## Migration Plan

1. 保持现有 CampusClaw 的班级和材料功能不变。
2. 在后端增加知识库处理与检索模块。
3. 为已有或新上传的班级材料增加知识库处理流程。
4. 增加知识检索接口，并确保接口使用班级范围过滤。
5. 在前端增加知识检索输入框、结果展示和来源展示。
6. 完成功能测试后逐步启用知识库检索功能。

如果新增知识库功能出现问题，可以暂时关闭知识库相关接口和页面，不影响原有材料上传、下载和作业功能。
